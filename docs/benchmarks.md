# 벤치마크 데이터와 평가 지표

## 평가 규약

### 외부 데이터와 프로젝트 사진의 구분

| 평가 | 데이터 | 정답 기하 | 실제 평가 대상 |
| --- | --- | --- | --- |
| HPatches | 116개 시퀀스, 각 첫 영상과 나머지 5장: 580쌍 | 제공된 호모그래피 H | 두 영상 정합의 전역 H와 국소 보정 후 좌표 |
| UDIS-D | 로컬 공식 배포본의 완전한 시험 영상 쌍 1,105개 | 해당 평가에 독립적인 정답 H 없음 | 워핑된 영상 간 공통 영역의 밝기·구조 일치 |
| 프로젝트 미션 | Q1~E2의 저장 PNG 165개와 원본 13장 | 독립적인 정답 파노라마·랜드마크 없음 | 최종 PNG를 원본 좌표로 역추적한 원본 일치도 |

HPatches는 정답 호모그래피가 있는 자료로 기하 평가에 사용했다. [공식 데이터 안내](https://github.com/hpatches/hpatches-dataset)
UDIS-D는 실제 장면 영상 쌍의 정합 성능을 비교하는 자료로 사용했다. 데이터와 참조 코드만 이용했으며 원 저장소의 학습 모델을 실행한 것이 아니다. [공식 배포 저장소](https://github.com/nie-lang/UnsupervisedDeepImageStitching)

UDIS-D의 보고된 시험 규모는 1,106쌍이지만, 사용한 배포본에는 `input1/000001.jpg`가 없어 완전한 1,105쌍을 평가했다. 누락 영상을 만들어 넣거나 다른 사진으로 대체하지 않았다. [다운로드 출처·해시](../data/benchmark_sources.json)

외부 벤치마크는 각 방법의 **Q1 두 영상 경로**를 사용한다. Q3의 8장 BA·E2 블렌딩 전체를 평가하는 시험은 아니다. 프로젝트 PNG에 같은 PSNR·SSIM 공식을 적용했다고 해서 그 수치가 HPatches나 UDIS-D 벤치마크 점수가 되는 것도 아니다.

### 기하 지표

- **Corner error:** 전역 H와 정답 H로 옮긴 네 모서리 사이 거리의 평균이다. 단위는 대상 원본 영상의 px이다. 보고서의 Corner 중앙값은 성공한 영상 쌍들의 오차 중앙값이다.
- **H AUC@t:** `100 × mean(max(1 − corner_error/t, 0))`. 여기서는 t=5px를 주로 사용한다. 실패는 0점이다. 임계값 이하인 영상의 비율인 성공률과는 다르다. 국소 보정 전 H를 사용하므로 같은 상위 설정의 없음/APAP/REW/DIS 값이 동일하다.
- **독립점 오차:** 기준 영상의 최대 20×20 격자 중 정답 변환 후 유효한 점에서, 최종 국소 보정까지 포함한 예측 좌표와 정답 좌표의 거리를 측정한다. 이 정답과 격자는 추정에 사용하지 않는다. 주 지표는 **영상 쌍별 점 오차 중앙값을 구한 후, 성공 영상 쌍들에 대해 다시 중앙값을 취한 값**이다. RMSE·P95도 별도로 기록한다.

기하 오차는 처리 성공 사례의 값이므로 반드시 실패 수와 함께 읽는다. 정답 H가 없는 UDIS-D 및 프로젝트 미션에는 정답 기준 기하 오차를 임의로 만들어 넣지 않는다.

### PSNR·SSIM

PSNR은 `10 log10(255² / MSE)`이며 단위는 dB, 높을수록 참조 픽셀과 가깝다. 계산에서는 완전 일치일 때 100dB로 제한한다. SSIM은 밝기·대비·구조 유사도를 비교하며 11×11 Gaussian 창(σ=1.5), K1=0.01, K2=0.03 및 BGR 채널 평균을 사용한다.

HPatches의 광도 점수는 정답 H로 정한 공통 지지 영역을 사용한다. UDIS-D의 주 점수는 33방법의 유효 마스크 교집합을 사용하며, SSIM 창 전체가 유효한 위치만 포함한다. 실패 영상 쌍은 명시적인 identity 대체 워핑으로 광도 평가에 남긴다. 즉 높은 PSNR/SSIM만으로 처리 성공이나 기하 정확도를 추론하면 안 된다.

UDIS 참조 코드 방식의 `masked_canvas_psnr_db`·`masked_canvas_ssim`도 원시 요약에 있으나, 마스크 밖 검은 픽셀이 점수를 부풀릴 수 있어 본문의 주 순위에는 사용하지 않는다. 본 보고서의 주 점수는 이 프로젝트의 명시된 평가 규약에 따른 값이며, 논문 표의 공식 수치와 직접 비교하지 않는다.

### 최종 PNG의 원본 일치도

실제 생성 과정의 호모그래피·카메라 투영·국소 변위장을 기록하고, 원본 사진의 좌표가 최종 PNG의 어디에 대응하는지 역추적한다. 원본 좌표 격자는 긴 변 최대 1,024개 표본으로 구성한다. 두 장 이상이 겹치며 해당 원본도 유효한 위치에서 모든 비교 방법의 교집합을 평가한다. DIS 결과에 전역 H만 적용하는 대체 평가는 하지 않는다.

미션 점수는 원본 입력별 PSNR/SSIM의 동일 가중 평균이다. E1과 E2는 같은 평가 영역을 공유하고, 서로 다른 미션을 하나의 총점으로 합치지 않는다. 원본 일치도에는 색상 보정·블렌딩·보간 손실·덮어쓰기 소유권의 영향도 포함된다. E2의 점수가 E1보다 낮다고 해서 블렌딩의 시각 품질이 나쁘다는 뜻은 아니다.

### 공통 영역과 집계 방식

최종 표는 33방법 공통 평가 기준이다. 17·25방법 단계의 점수와 수치만 직접 빼지 않는다. ‘국소 보정 종류별 평균’은 동일한 8개 검출기/기술자/추정기 조건의 **방법별 집계값을 산술 평균**한 것이다. HPatches의 그 평균은 전체 점을 합친 단일 중앙값과 다르다. B0는 이 8조합 평균에서 제외한다. 통계적 유의성 검정이나 신뢰구간은 산출하지 않았다.

## 실행과 출력

- `python stitching.py --task benchmark --workers 4`: 로컬 HPatches·UDIS-D를 평가하고 `docs/benchmark_results.md`를 갱신한다.
- `python stitching.py --task evaluate --workers 2`: 선택한 미션의 PNG를 생성하고 원본 좌표 평가를 수행해 `docs/mission_results.md`를 갱신한다.
- `--case`, `--method`, `--mission`, `--dataset`으로 범위를 제한할 수 있다. `--limit N`은 선택한 데이터셋마다 최대 N쌍인 시험 실행이며 전체 점수가 아니다.
- `--report /tmp/pilot.md`처럼 다른 Markdown 경로를 지정하면 보존된 결과 문서를 덮어쓰지 않는다. 이미지 출력 폴더 안에는 보고서를 저장하지 않는다.
- 미션 평가에 필요한 기하 캐시는 시스템 임시 디렉터리에서만 사용하고 정상 종료·예외 처리 시 제거한다. `results/`에는 최종 PNG만 저장한다.
- 외부 평가는 원시 JSON·CSV·중간 체크포인트를 저장하지 않는다. 프로세스가 중단되면 해당 실행을 다시 시작해야 한다.
- 같은 입력의 특징점·매칭은 영상 쌍 내부에서 재사용한다. 방법별 실행 시간은 독립적인 속도 순위에 사용하지 않는다.

## 현재 보존된 결과의 성격

[벤치마크 결과](benchmark_results.md)와 [미션 결과](mission_results.md)는 정리 이전 최종 33방법 평가의 측정 기록이다. 코드·입력·라이브러리 버전·선택한 방법 수가 바뀌면 같은 수치를 보장하지 않는다. 원시 결과 이미지·로그·개별 스냅샷은 사용자의 정리 요청에 따라 삭제했다. 새 통합 실행 경로의 회귀 검증 범위는 두 결과 문서에 기록한다.

[README](../README.md)에 공식 참조 저장소 clone, 데이터 다운로드·해시 검사·압축 해제 명령이 있다. 참조 저장소는 실행 시 import하지 않으며, 정합·평가는 OpenCV·NumPy와 Python 표준 라이브러리만으로 수행한다.
