# hdy: 단순화한 스티칭 코드의 Q1·Q2·Q3·E1·E2 결과

2026-11-28 기준 현재 공유 코드: 저장소 최상위 `stitching_hdy.py`.

## 무엇을 바꿨나

이전의 문제별 Brown–Lowe·RootSIFT/MAGSAC·APAP식 조합을 하나의 특징점 기반 흐름으로 교체했습니다. **SIFT 검출 → 양방향 Lowe 비율 매칭 → RANSAC으로 이상치 제거 → 전역 정렬 → 투영 → 합성** 순서입니다. `cv2.Stitcher`와 딥러닝 모델을 사용하지 않으며, 외부 사용자 정의 `.py` 파일을 불러오지 않습니다. 8장 공동 카메라 배치 아이디어는 같은 팀의 `stitching_Lsb.py`를 참고했습니다. Brown–Lowe 논문의 전체 시스템을 그대로 재현한 구현이라고 주장하지 않습니다.

| 미션 | 입력 | 정렬·투영 | 합성 |
| --- | ---: | --- | --- |
| Q1 | 2장 | SIFT·RANSAC 평면 호모그래피 | 5밴드 멀티밴드 블렌딩 |
| Q2 | 3장 | 사진 3장의 카메라 회전 공동 추정, 원통 투영 | 5밴드 멀티밴드 블렌딩 |
| Q3 | 8장 | 사진 8장의 카메라 회전 공동 추정, 원통 투영 | 5밴드 멀티밴드 블렌딩 |
| E1 | Q3와 같은 8장 | 공동 카메라 회전 추정, 구면 투영 | 한 사진의 픽셀을 선택해 연결, **블렌딩 없음** |
| E2 | Q3와 같은 8장 | E1과 같은 구면 정렬 경로 | 5밴드 멀티밴드 블렌딩 |

과제 안내문은 멀티밴드 블렌딩 자체를 금지하지 않습니다. E2를 `+ blending` 단계로 명시하므로 E1과 E2의 차이를 위와 같이 분명히 유지합니다. Q1·Q2·Q3에도 블렌딩을 사용했다는 점은 발표에서 밝힙니다.

Windows, Python 3.12.10, OpenCV 4.11.0, NumPy 1.26.4에서 **과제 제공 `run.py`를 수정하지 않고** 다음 명령으로 확인했습니다.

```bash
python run.py --q all --code stitching_hdy.py --out results/hdy_check
```

## 점수와 해석 범위

**현재 코드의 Test RMSE와 블렌딩 전 겹침 SSIM은 아직 계산하지 않았습니다.** 이 문서에는 임의의 점수를 넣지 않습니다. [이전 방법 비교 문서](hdy_method_comparison.md)의 RMSE·SSIM은 과거 코드와 사진을 평가한 기록이며, 현재 `stitching_hdy.py`나 이 ZIP에 적용할 수 없습니다. 특히 Q3·E1·E2에는 별도로 검토된 미사용 특징점이 없어 Test RMSE를 제시하지 않습니다.

코드는 사진들을 긴 변 1400픽셀 이하로 축소하고, 공동 카메라 추정에 한 미션 안의 입력 사진 크기가 같다는 조건을 둡니다. 이번 입력에서는 다섯 미션이 실행됐지만 다른 촬영 장면이나 크기가 다른 사진에서의 품질은 검증하지 않았습니다. 동일 환경에서 Q3를 다시 실행했을 때 구도와 크기는 같았고 약 0.13% 픽셀에 작은 값 차이가 있어 바이트 단위 동일성은 주장하지 않습니다.

제출 시에는 이 단일 파일을 `stitching.py`로 이름을 맞춰 과제 제공 `run.py`로 다시 확인해야 합니다. `run_hdy.py`는 팀 공유용 실행기입니다.
