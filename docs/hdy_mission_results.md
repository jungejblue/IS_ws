# hdy: Q1·Q2·Q3·E1·E2 미션 결과

## 공유 범위와 실행

`stitching_hdy.py`는 과제 규정 안에서 미션별 방법을 선택한 **단일 파일**입니다. Q1은 Brown–Lowe 계열, Q2는 RootSIFT·MAGSAC 변형, Q3·E1·E2는 Brown 전역 배치를 초기값으로 쓰는 APAP식 Moving DLT입니다. `run_hdy.py`는 팀원 확인용 실행기이며, 과제에서 제공한 `run.py`와 저장소의 기존 `stitching.py`는 수정하지 않았습니다. 이 공유 파일에서 개발용 평가·CSV·시각화 저장 코드는 제외했습니다. **최종 과제 제출에는 파일 이름을 `stitching.py`로 맞추고 제공된 `run.py`로 검사**해야 합니다.

```bash
python run_hdy.py --q all --out results/hdy
# 과제 제공 실행기로 같은 코드를 검사할 때:
python run.py --q all --code stitching_hdy.py --out results/hdy_check
```

Python 3.10 이상과 OpenCV(contrib 포함), NumPy가 필요합니다. 입력은 이 저장소의 `data/Q1`, `data/Q2`, `data/Q3`입니다. Q3는 8장의 위쪽 행 1–4, 아래쪽 행 5–8 순서입니다. 이번 결과의 Q3 입력 식별자는 `c013af857a8a`이며, 이 저장소의 `.jpeg` 파일 8개와 실험 당시 `.jpg` 파일 8개의 **내용 해시가 각각 같습니다**. 입력 파일명과 확장자만 다릅니다.

ZIP의 다섯 PNG를 **바이트 단위로 동일하게 재생성한 검증 환경**은 Windows, Python 3.12.10, `opencv-contrib-python 5.0.0.93`, `numpy 2.5.5`입니다. 저장소의 `requirements.txt`로 설치되는 OpenCV 4.11.0.86·NumPy 1.26.4 환경에서도 다섯 미션은 모두 성공했지만, 일부 결과의 크기와 픽셀이 달랐습니다. 따라서 버전이 다른 실행 결과에 아래 저장된 평가 수치를 그대로 붙이지 않습니다. 두 버전 계열을 각각 별도 가상환경에서 실행했습니다.

완성 PNG 5장은 Git 저장소에 넣지 않고 `hdy_final_results_Q1_Q2_Q3_E1_E2.zip`으로 별도 전달합니다. ZIP에는 `Q1_result.png`, `Q2_result.png`, `Q3_result.png`, `E1_result.png`, `E2_result.png`만 있습니다. Q3는 교체된 새 사진 8장으로 만든 결과이며, 이 ZIP은 **한 알고리즘의 5장 결과가 아니라 아래에서 선택한 방법별 결과**입니다.

`run_hdy.py --q all`은 완성 PNG와 실행 상태 JSON을 만들지만 특징점 그림이나 아래 지표를 자동 생성하지는 않습니다. 지표는 개발 단계에서 별도 검토점과 사진 쌍별 평가 자료를 사용해 측정한 기록입니다.

## 무엇을 구현했나

| 미션 | 입력 | 투영·정합 | 합성 |
| --- | ---: | --- | --- |
| Q1 | 2장 | Brown–Lowe 계열 SIFT·RANSAC 평면 호모그래피 | 중심 가중치와 멀티밴드 블렌딩 |
| Q2 | 3장 | 원통 투영, SIFT 특징점의 RootSIFT 기술자, MAGSAC 호모그래피 | 멀티밴드 블렌딩 후 크롭 |
| Q3 | 8장 | 원통 투영, SIFT·RANSAC 전역 배치, APAP식 국소 Moving DLT | 접합선 선택과 멀티밴드 블렌딩 |
| E1 | Q3와 같은 8장 | 구면 투영, SIFT·RANSAC 전역 배치, APAP식 국소 Moving DLT | 블렌딩 없는 연결 |
| E2 | Q3와 같은 8장 | E1과 동일한 투영·정합·배치 | 6단계 멀티밴드 블렌딩 |

제출형 단일 파일로 다섯 미션을 다시 실행했습니다. Q1은 기존 Brown–Lowe 결과, Q2는 기존 F06 변형 결과, Q3·E1·E2는 기존 APAP 결과와 **각각 픽셀 단위로 일치**합니다. E1과 E2는 같은 정합 좌표를 쓰므로 차이는 블렌딩에 있습니다. 완성 사진에는 일부 접합 경계가 남습니다. 이 구현은 APAP 논문의 전체 시스템 재현이 아니라 Brown 전역 배치 위에 Moving DLT를 결합한 다중 이미지 포트입니다.

## 측정 결과

| 미션 | Test RMSE ↓ | 블렌딩 전 겹침 SSIM ↑ | 측정 범위 |
| --- | ---: | ---: | --- |
| Q1 | 0.2287 px | 0.9929 | 검토한 시험 대응점 40개, 사진 쌍 1개 |
| Q2 | 4.8764 px | 0.6079 | 검토한 시험 대응점 80개, 사진 쌍 2개 |
| Q3 | 평가 불가 | 0.3269 | 새 Q3의 가로 방향 사진 쌍 6개 |
| E1 | 평가 불가 | 0.3744 | 구면 투영 후 가로 방향 사진 쌍 6개 |
| E2 | 평가 불가 | 0.3744 | E1과 같은 블렌딩 전 정합 결과 |

RMSE는 별도로 검토하고 정합 추정에 사용하지 않은 대응점의 재투영 오차입니다. Q1의 단위는 첫 사진의 원본 좌표계 px, Q2는 원통 투영된 둘째 사진의 좌표계 px입니다. Q2는 두 사진 쌍에서 **각각 40점의 RMSE를 계산한 뒤 쌍별 값을 단순평균**했으며 SSIM도 두 쌍의 값을 단순평균했습니다. Q1·Q2의 값은 검토된 **표본**에 대한 결과이며 전체 장면의 기하 정답이 아닙니다. 새 Q3·E1·E2에는 독립적으로 검토한 시험 대응점이 없어 RMSE를 계산하지 않았습니다.

특히 Q2의 RMSE용 호모그래피는 검토점을 빼고 매칭점으로 **별도 재추정**했습니다. 최종 PNG와 SSIM에 사용한 호모그래피는 전체 자동 매칭점으로 추정했으므로 4.8764 px를 최종 PNG의 변환 행렬 자체에 대한 오차라고 해석하면 안 됩니다. 또한 이 평가값으로 방법을 선택했으므로, 검토점은 변환 추정에서는 독립적이지만 **방법 선택 이후의 독립 최종 시험 세트는 아닙니다.**

Q2의 0.6079 SSIM은 F06 변형과 Brown–Lowe 두 방법이 공유하는 평가 영역에서 계산한 값입니다. 같은 조건에서 Brown–Lowe는 RMSE 5.2920 px, SSIM 0.5960이었습니다. 이전 8방법 비교표의 Brown–Lowe Q2 SSIM 0.5993은 **참여 방법이 다른 공통 평가 영역**이므로 0.6079와 직접 뺄셈하지 않습니다. Q3의 0.3269와 E1·E2의 0.3744는 선택된 APAP 코드의 실제 블렌딩 전 워프·마스크로 다시 계산했고, 저장된 APAP 실험과 픽셀 단위로 일치했습니다.

SSIM은 완성 파노라마에 계산한 점수가 아닙니다. 블렌딩 전의 정렬된 두 사진을 같은 좌표계에 놓고, 실제 픽셀이 있는 공통 겹침 영역에서 회색조 11×11 Gaussian 창으로 계산했습니다. 창 전체가 유효한 위치만 포함합니다. 같은 미션 안에서는 알고리즘별 공통 평가 영역을 썼지만, **Q1·Q2·Q3·E1의 평가 영역과 투영은 서로 다르므로 미션 사이 숫자로 순위를 매기면 안 됩니다.** 노출·밝기 차이도 SSIM에 영향을 줍니다. E2의 블렌딩 효과는 완성 사진에서 별도로 확인해야 합니다.

Q3·E1·E2의 SSIM은 **가로로 이웃한 6쌍**만 측정했습니다. 위아래 행의 연결부를 점수로 검증한 것은 아닙니다. 아래 행 중심의 접합선 선택은 현재 Q3 장면에 맞춘 설정이어서 다른 2×4 촬영 장면에서 같은 품질을 보장하지 않습니다.

다른 알고리즘과의 같은 미션 내 비교, 실패 사례 및 방법별 결함은 [hdy_method_comparison.md](hdy_method_comparison.md)에 기록했습니다. 이 수치는 hdy의 로컬 실험에서 얻은 값이며 기존 팀원 문서의 수치를 재측정한 값으로 표시하지 않습니다.
