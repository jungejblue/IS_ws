# 방법별 프로젝트 미션 결과

## 매칭 신뢰도 정책 수정 후 재출력

`cv_stitch`의 Python 3.11.17 / OpenCV 4.14.0 / NumPy 2.4.6에서 중복 영상 억제 상한을 3.5로 명시한 뒤 33케이스의 다섯 미션을 다시 실행했다. 165개 모두 생성에 성공했고, 각 PNG의 BGR uint8 디코딩·케이스별 파일 구성·재생성 시각을 확인했다. `results/`에는 PNG만 있으며 Git 추적에서 제외된다. 이 재실행에서는 PSNR·SSIM을 재산출하지 않았으므로 아래 표는 기존 측정 기록으로 유지한다.

이 문서는 정리 이전 `local_warps_dis_v1` 실험의 측정값을 보존한 기록이다. Python 3.10.12 / OpenCV 4.5.4 / NumPy 1.26.4, OpenCV·BLAS 단일 스레드에서 평가했다. 방법 코드는 [알고리즘 문서](algorithm.md), 지표와 집계 방식은 [벤치마크·평가 지표](benchmarks.md)를 따른다. 원시 PNG·로그·캐시·실행 스냅샷은 정리 요청에 따라 삭제하고 수치 표만 보존했다.

나머지 상위 세 변인을 고정한 8쌍에서 DIS−기준 방법의 차이를 구해 평균했다. PSNR/SSIM은 양수일 때 개선이다.

| 미션 | DIS−없음 PSNR / SSIM | DIS−APAP PSNR / SSIM | DIS−REW PSNR / SSIM |
| --- | --- | --- | --- |
| Q1 | -1.277 / -0.00012 | -0.935 / -0.00008 | -1.074 / -0.00014 |
| Q2 | +2.862 / +0.19254 | +2.330 / +0.10921 | +2.342 / +0.11087 |
| Q3 | +1.254 / +0.11995 | +1.108 / +0.08090 | +1.198 / +0.09276 |
| E1 | +1.302 / +0.12875 | +1.126 / +0.08742 | +1.221 / +0.10100 |

Q2~E2에서는 DIS 평균 PSNR과 SSIM이 모두 개선됐다. Q1에서는 평균 PSNR이 낮아지고 SSIM도 소폭 감소했다. 이는 잔여 시차가 있는 장면에 유용한 보정이 이미 잘 맞는 장면에서는 불필요한 변형·보간을 추가할 수 있음을 시사한다. 이는 결과에 대한 해석이며, 본 실험만으로 모든 장면의 원인을 확정한 것은 아니다.



## Q2 경계 개선과 정성 평가

### 전체 사진이 비슷해 보였던 이유

검출기·기술자·강건 추정을 바꾸어도 비슷한 전역 기하가 추정되면 전체 파노라마의 모양은 거의 같다. APAP·REW 단계에서는 수 px 정도의 국소 이동이 큰 파노라마를 축소한 화면에서 잘 드러나지 않았다. 이전 25방법 파일 검사에서는 Q2·Q3·E1·E2의 PNG가 각각 모두 달랐지만, Q1은 25개 중 고유 파일이 21개로 일부 조합이 실제로 동일했다. 파일 차이가 존재한다는 사실 자체도 정합 품질 향상의 증거는 아니다. 당시 파일 해시·픽셀 비교 검사

### Q2 DIS 개발 진단

도로의 노란 선과 보도 턱이 사진 경계에서 끊기는 것을 확인하고, 전역 워핑 뒤에 DIS를 추가했다. 이 개발 실험은 Brown–Lowe 기반 기본 실행에 대한 보정 전후 비교이며, 최종 D00~D07의 NumPy BA 조합과 구분한다. 최종 결과는 단순 덮어쓰기를 유지하므로 밝기 차이도 그대로 보인다.

정답이 없는 진단에서는 별도의 Shi–Tomasi/Lucas–Kanade 추적으로 얻은 같은 대응점을 보정 전후 비교했다. 아래는 뒤쪽 영상 경계 안쪽 120px 표본이다. 이 대응점은 DIS fitting 입력으로 쓰지 않았지만, 같은 이미지에서 추정된 값이므로 독립적인 정답 기하 검증은 아니다.

| 영상 쌍 | 표본 수 | 중앙 오차 전→후(px) | P95 전→후(px) |
| --- | --- | --- | --- |
| 1-2 | 55 | 6.541 → 2.079 | 13.776 → 6.268 |

보도 턱·도로선·건물 윤곽의 연결이 개선됐지만 밝기 경계와 일부 위치 잔차는 남았다. 초기 평활화 없는 광류 후보에는 접힘이 발생해 채택하지 않았으며, 최종 구현은 평활화와 Jacobian 조건을 통과한 변위만 사용했다. 위 진단값을 HPatches·UDIS-D 점수나 최종 8조합 평균에 합산하지 않는다.

## 새 결과 생성과 평가

```bash
# 165개 PNG만 생성
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -B stitching.py --workers 2

# PNG를 생성하고 이 결과 문서도 새 점수로 갱신
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -B stitching.py --task evaluate --workers 2
```

출력은 `results/<방법>/<케이스>/<미션>_result.png`이다. 결과 폴더에는 이미지 외의 파일을 저장하지 않는다. E1/E2를 따로 선택해 평가하면 둘을 함께 평가한 공통 영역과 달라질 수 있으므로 직접 점수를 빼지 않는다.

## 실행기 통합 후 검증

새 `stitching.py` CLI로 33케이스 × 5미션을 실제 생성·평가했다. 165개 PNG가 이전 결과와 픽셀 단위로 완전히 일치했고, 165개 미션의 PSNR(소수 3자리)·SSIM(소수 5자리)·공통 면적(소수 2자리)도 기존 측정값과 일치했다. 결과 폴더에 PNG 외의 파일이 없는 것을 확인했다. 검증용 PNG·보고서·기하 캐시는 정리 후 남기지 않는다.
