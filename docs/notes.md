# 개발 주의사항

## 과제 계약

- `run.py` 수정 금지. 입력 경로는 `img_paths`에서만 읽습니다.
- `stitching.py`는 독립된 단일 파일이며 외부 로컬 모듈을 import하지 않습니다.
- CV 라이브러리는 OpenCV만 사용하고 NumPy 연산은 허용합니다.
- `cv2.Stitcher`/`Stitcher_create` 사용 금지. 단계별 처리와 설명을 유지합니다.
- Q1/Q2는 2장·3장, Q3/E1/E2는 2×4 순서의 8장입니다.

## 실험 비교

루트 기본 설정과 `brown_lowe_assignment` 실험 프로필을 구분합니다. 후처리 OFF에도 기하 워핑 보간은 적용됩니다. E2만 gain·multi-band를 사용한다는 조건은 현재 비교 실험의 선택이며, 공지가 다른 미션의 모든 후처리를 금지한다고 해석하지 않습니다.

baseline의 다중영상 BA는 OpenCV, 네 개선 방법은 NumPy 구현입니다. B0 대비 다중영상 변화에는 solver 차이가 포함됩니다. APAP 구현은 과제용 Moving DLT 확장으로 원 논문 전체 재현이 아닙니다.

코드 변경 시 다음 정보를 남깁니다.

| 항목 | 기록 |
| --- | --- |
| 입력 | 파일 순서·장수·해시, 새 Q3 여부 |
| 방법 | 기술자·추정기·BA·APAP 설정 |
| 투영 | 평면/원통/구면, 넓은 시야 처리 경로 |
| 후처리 | gain·마스크·블렌딩 조건 |
| 평가 | 참조·좌표·마스크·실패 처리·집계법 |
| 환경 | Python/OpenCV/NumPy, 스레드·실행 명령 |

## 기존 파일 보존

원본 사진을 평가 편의를 위해 재압축하지 않습니다. 스냅샷은 과거 실험의 증거이므로 개발용으로 직접 편집하지 않습니다. 제출본은 별도 `submission/`에서 선택한 스냅샷을 정리하고 검증합니다.

`experiments/run_methods.py`는 선택한 방법 폴더의 스냅샷과 manifest를 갱신합니다. 단순 재현에는 `run.py --code ... --out results/local/...`를 사용합니다.

## 확인 수준

문서 변경은 링크·명령·표를 확인하고, 수치·좌표 코드 변경은 로컬에서 확인한 방법과 결과를 PR에 기록합니다. 테스트 코드와 테스트용 CI는 삭제했으며, 다시 생성되어도 Git에서 제외합니다. 실제 정합 로직 변경은 해당 미션을 실행합니다. 숫자 차이가 있으면 이전 기록을 새 결과인 것처럼 유지하지 않습니다.
